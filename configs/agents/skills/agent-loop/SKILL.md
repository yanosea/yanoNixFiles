# Explicit development loop

Start only after the user has authorized the concrete scope and acceptance conditions. Show the ordered tasks, actual check commands, and criteria before starting. Do not infer permission from a Stop event. Use the existing project plan; do not expand scope or skip a task.

Run `agent-loop identity --workspace "$PWD"` to list identities actually observed by native hooks. Select the identity of this session from the native context. Never invent a session ID or take another session merely because it is the newest. If identity cannot be established, stop and explain that automatic continuation cannot safely be enabled. The CLI refuses unobserved identities.

This complete example uses an existing Python Git project with a unittest suite. Adapt the task and commands to the approved project plan. Set `AGENT_LOOP_SESSION` to the exact native session ID from context and `AGENT_LOOP_HARNESS` to its observed harness name; neither value is generated by the example.

```bash
: "${AGENT_LOOP_SESSION:?Set the observed native session ID}"
: "${AGENT_LOOP_HARNESS:?Set the observed native harness}"
python3 - <<'PY'
import json
import os
from pathlib import Path
spec = {
    "workspace": os.getcwd(),
    "artifact_paths": ["tests/__pycache__"],
    "tasks": [{
        "id": "repair", "title": "Implement the approved repair",
        "criteria": [{"id": "behavior", "text": "The approved behavior is implemented and covered by the regression suite", "kind": "agent"}],
        "commands": [{"argv": ["python3", "-m", "unittest", "discover", "-s", "tests"], "timeout": 120}]
    }]
}
Path('/tmp/agent-loop-spec.json').write_text(json.dumps(spec))
PY
AGENT_LOOP_ID="$(agent-loop start --spec /tmp/agent-loop-spec.json --harness "$AGENT_LOOP_HARNESS" --session "$AGENT_LOOP_SESSION" | python3 -c 'import json,sys; print(json.load(sys.stdin)["id"])')"
agent-loop status --workspace "$PWD"
```

Implement the current task and run `agent-loop check --loop-id "$AGENT_LOOP_ID" --workspace "$PWD" --harness "$AGENT_LOOP_HARNESS" --session "$AGENT_LOOP_SESSION"`. After examining actual current content and check results, attach concrete evidence:

```bash
agent-loop record --loop-id "$AGENT_LOOP_ID" --workspace "$PWD" --harness "$AGENT_LOOP_HARNESS" --session "$AGENT_LOOP_SESSION" --task repair --criterion behavior --evidence 'Describe the actual changed behavior and observed regression result here.'
```

Replace the example evidence with observed facts. A record alone cannot pass checks. Later edits make old criterion evidence historical; re-inspect and re-record stale criteria during the fresh final pass. Registered project providers are mandatory, even when omitted from the spec. The final pass reruns every task check and provider. Completion requires all current-content evidence and all final checks.

A human criterion enters `waiting`. Ask for the actual user's review. After it arrives, `agent-loop confirm-human --loop-id "$AGENT_LOOP_ID" --workspace "$PWD" --task TASK --criterion CRITERION --quotation 'Verbatim user confirmation' --reference 'Actual message reference'` records it. Never manufacture the quotation, replace human review with agent evidence, or claim independent review. No OS authentication is provided: this command records the user's confirmation as reported by its caller.

Use `agent-loop pause --loop-id "$AGENT_LOOP_ID" --workspace "$PWD"` or `agent-loop cancel --loop-id "$AGENT_LOOP_ID" --workspace "$PWD"` when requested. `agent-loop resume --loop-id "$AGENT_LOOP_ID" --workspace "$PWD" --harness "$AGENT_LOOP_HARNESS" --session "$AGENT_LOOP_SESSION"` explicitly adopts ownership and reruns checks. Previous owners and leases are revoked. A native lifecycle restart, fresh user input, approval/auth/service wait, abort, or unknown delivery requires inspection and explicit resume. Never resend an uncertain API continuation. Three repeated nonprogress attempts, including cycles, enter `blocked`; diagnose before resuming. There is no total iteration/time cap; each check has its own timeout and product/user stop requests take precedence.

The ledger is not a shell sandbox. Only put reviewed, explicit check argv in the spec. Git ignores and explicitly reviewed `artifact_paths` exclude generated artifacts from content fingerprints; registered providers must fingerprint relevant external/ignored data. Do not store a changing log or spec inside the tracked workspace unless it is part of the approved scope.
